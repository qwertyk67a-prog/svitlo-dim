# Позаграфікові відключення: однобудинкове сповіщення

Мета: мешканці одного будинку отримують **нові офіційні відомості ДТЕК**, коли світло вже могло зникнути і графік ще не відображає проблему.

## Точне правило

1. Якщо ДТЕК повідомив про аварію, ремонт, нове ГПВ чи змінив час і подія **стосується адреси**, повідомити один раз.
2. Якщо ДТЕК повідомив про екстрені, аварійні або часткові відключення **на території, до якої входить будинок**, повідомити один раз. Це не підтверджує знеструмлення конкретного будинку.
3. Якщо ДТЕК повідомив про подію тільки на іншій території, **мовчати**.
4. Якщо ДТЕК ще нічого не повідомив, **мовчати**, навіть якщо в мешканців фактично немає світла.
5. Якщо інформація надійшла **після зазначеного часу початку**, повідомити при виявленні. Підписати минулий час початку як дані ДТЕК, а не як власне вимірювання.
6. Якщо ДТЕК уточнив суттєвий статус події, повідомити про нові відомості. Незмінний статус не дублювати.
7. Якщо ДТЕК повідомив про скасування чи завершення раніше відомої події, сповістити лише після попереднього повідомлення про неї. Не обіцяти відновлення світла в кожній квартирі.

## Повідомлення ДТЕК, оприлюднене після завершення відключення

- Якщо відключення **вперше** з'явилося в адресних даних ДТЕК, а зазначений час завершення **вже минув**, не надсилати повідомлення.
- Якщо ГПВ на сьогодні вперше містить **тільки вже завершені інтервали**, зберегти стан для уникнення повторів, але **не надсилати повідомлення**.
- Якщо у новому графіку є актуальні або майбутні інтервали, повідомити лише про них. Минулі інтервали не видавати за майбутні.
- Якщо офіційний канал ДТЕК містить і початок, і завершення однієї регіональної події до чергової перевірки, а попереднього сповіщення не було, **мовчати**.
- Якщо подію раніше вже оголосили мешканцям, а ДТЕК повідомив про її дострокове скасування, повідомити про скасування.
- Якщо ДТЕК **не зазначив достовірний час завершення**, не робити самостійного висновку, що електроенергія вже відновилася.
- Якщо ДТЕК зазначив однозначний час завершення всередині нової регіональної публікації, а час уже минув, не надсилати нове повідомлення про початок.

**Це фільтр за часовими даними ДТЕК.** Він не підтверджує фактичне повернення напруги.

## Географічна відповідність

| Повідомлення ДТЕК | Реакція |
|---|---|
| Аварія за точною адресою будинку | Сповіщати |
| Частково знеструмлено наш квартал | Сповіщати з приміткою: **невідомо, чи зачепило саме будинок** |
| Частково знеструмлено наш район | Сповіщати з тією самою приміткою |
| Частково знеструмлено наше місто або область | Сповіщати з приміткою про невизначеність стану будинку |
| Обмеження по всій Україні | Сповіщати |
| Обмеження в **деяких областях України**, але які саме — невідомо | **Не робити висновку, що наша область охоплена** |
| Чітко зазначено лише інше місто, район, квартал чи будинок | Мовчати |
| Немає нових офіційних даних | Мовчати |

**Важливо:** на практиці текстові повідомлення можуть бути неоднозначними. Фільтр повинен відмовлятися від непідтверджених географічних висновків.

## Конфігурація через Repository Secret

Три основні поля залишаються обов'язковими для адресної перевірки ДТЕК.
Для повідомлень **на рівні району або кварталу** додайте два необов'язкові поля до **того самого** секрету `DTEK_ADDRESS_JSON`:

```json
{
  "city": "НАСЕЛЕНИЙ_ПУНКТ",
  "street": "ВУЛИЦЯ",
  "house": "БУДИНОК",
  "district": "НАЗВА РАЙОНУ",
  "quarter": "НОМЕР КВАРТАЛУ"
}
```

Значення `district` і `quarter` використовуються **тільки для зіставлення географії** у повідомленнях ДТЕК.
До самого адресного запиту ДТЕК надсилаються лише `city`, `street`, `house`.
Поки ці два поля відсутні, повідомлення лише про район або квартал без чіткої прив'язки до міста можуть залишитися непоміченими. Бот не вигадує район за назвою вулиці.

**Увага:** GitHub не дозволяє прочитати вже збережений Secret. Відредагуйте його повним правильним JSON, не публікуючи значення в коді чи чаті.

## Що бот знає, а чого не знає

- **Знає:** новий підтверджений ГПВ, зміни графіка, адресні події, деякі офіційні територіальні повідомлення.
- **Не знає:** чи фізично зникло світло, наявність напруги у квартирі та реальний момент відновлення без офіційних даних.
- **Не використовує:** повідомлення мешканців, датчики напруги та сторонні свідчення. Ці джерела не додаються без окремого рішення.
- **Не може гарантувати:** що будь-який довільний текст чи повідомлення ДТЕК буде розпізнано. Фільтр наразі обробляє обмежені структури офіційного Telegram-каналу та адресного API.

## Приклад територіального повідомлення

**ДТЕК: часткові відключення у районі.**

«Зазначена територія включає ваш будинок. Невідомо, чи зачепило відключення саме будинок. Час відновлення ДТЕК не зазначив.»

Текст не повинен стверджувати, що будинок уже без світла.

## Затримки

Розклад GitHub Actions запитує перевірку кожні 5 хвилин. Запуск може бути затриманий або пропущений.
Тому **«повідомити негайно після виявлення» означає обробити подію в найближчому фактичному запуску**, а не гарантію доставки за 5 хвилин.

Адресний API: https://www.dtek-dnem.com.ua/ua/shutdowns
