# Відключення вже сталося, а ДТЕК повідомив пізніше

Мета: мешканці отримують **нову корисну інформацію**, коли світло вже могло зникнути, навіть якщо планового ГПВ раніше не було або він указував пізніший час.

**Суттєве обмеження:** цей бот не підключений до електрощита, лічильника або сенсора. Він **не може підтвердити фізичне зникнення чи повернення електроенергії** тільки за таблицею відключень.

## Сценарії

| Що відбувається | Як реагує бот |
|---|---|
| ДТЕК підтвердив аварію саме за захищеною адресою, час її початку минув | Відправити одне термінове адресне повідомлення. Указати час початку за даними ДТЕК, час виявлення інформації, причину та орієнтовне завершення або «не зазначено». |
| ДТЕК додав нове підтверджене відключення в ГПВ, яке **вже припадає на поточний час** | Пріоритетне оновлення ГПВ з поясненням, що за новим графіком час початку вже настав. Не стверджувати, що електроенергії фізично немає. |
| За ГПВ відключення о 20:00, але на годиннику 17:00 світло зникло; ДТЕК ще нічого не повідомив | Без зовнішнього сигналу бот **не може знати про зникнення**. Не надсилати вигадане повідомлення або неправдиву «причину». |
| ДТЕК пізніше опублікував регіональний екстрений режим | Повідомити про офіційний режим, час публікації та те, що це **не підтвердження відключення саме будинку**. |
| Бот увімкнули вперше під час нещодавно оголошеного екстреного режиму | Якщо останнє регіональне повідомлення про цей режим активне й опубліковане не більш ніж 2 години тому, відправити повідомлення лише один раз. Стару історію не надсилати. |
| ДТЕК скасував екстрений режим або повідомлення за адресою | Повідомити один раз лише якщо раніше було сповіщення про цей режим/адресну подію. Не обіцяти, що світло вже відновлено. |
| ДТЕК повідомив про орієнтовне відновлення, а час змінився | Повідомити тільки при зміні часу чи суті події. |
| ДТЕК не відповідає або повернув неоднозначні дані | Не перетворювати помилку на фальшиве «аварію ліквідовано» чи «світло є». |

## Ступені достовірності

1. **Підтверджене адресне оголошення ДТЕК:** інформація про конкретний будинок.
2. **Регіональна подія ДТЕК:** тільки оголошення для області/міста, не факт відключення будинку.
3. **Зміни ГПВ:** поточний офіційний графік, а не фізичне вимірювання.
4. **Повідомлення мешканця** (поки не реалізовано): свідчення людини, а не офіційний висновок.

**Не слід змішувати «за графіком вимкнено» й «фактично немає напруги».** Вимкнення поза графіком може бути аварійним, екстреним або внутрішньобудинковою проблемою, причому без перевірки причина невідома.

## Незалежний сигнал, якщо ДТЕК мовчить

Надалі можна додати **команду адміністратора Telegram або анонімні структуровані повідомлення мешканців**:
- Одне повідомлення користувача: лише «отримано повідомлення про відсутність світла», без твердження, що весь будинок знеструмлений.
- Для підтвердження декількох незалежних звернень потрібен антиспам і захист від маніпуляцій, з урахуванням кількох черг в одному будинку.
- Після офіційної відповіді ДТЕК — окреме підтвердження чи уточнення причини.
- Не розкривати імена, телефони, квартири та Telegram ID мешканців у публічному каналі.

**Цей режим НЕ впроваджено зараз.** Нинішній бот односпрямовано надсилає Telegram-повідомлення. Вхідні команди не читаються.

## Практичні правила

- Доставка залежить від доступності ДТЕК, інтернету, Telegram та фактичних запусків GitHub Actions.
- Запитаний інтервал запуску кожні 5 хвилин **не гарантується** хостингом.
- ДТЕК має офіційну можливість повідомити про відсутність електроенергії та перевірити стан заявки. Ці дії не виконуються від імені мешканців без їхньої згоди.
- За відсутності світла поза графіком мешканці можуть повідомити ДТЕК або ОСББ через офіційні канали.
- Усі повідомлення тільки українською.
- Не створювати повторів, якщо офіційні дані не змінювалися.
