# SVITLO-DIM: additional safety audit — 22 November 2026

**Scope:** reusable feature branch only. The active `main` bot and its
Cloudflare scheduler were deliberately left running, without cutover.

## Fixed and regression-tested

1. **Telegram token rotation:** the checkpoint namespace excludes token
   credentials. Address identity and Telegram chat still determine ownership.
2. **Same building spelling:** normalized Latin A/B/I aliases and punctuation
   before letter suffixes no longer reset delivered-history state. Numeric
   house slashes are preserved, so `1/1` is never treated as `11`.
   Purely descriptive district/quarter corrections do not reset history.
3. **Checkpoint migration:** active `official:status:*` emergency and
   GAV state now survives the one-time move to `bot-state`.
4. **Cloudflare continuity:** Wrangler `ENABLED=true` in this branch,
   matching the deployed production scheduler. Do not automatically disable
   a live Worker when merging this PR.
5. **Cached queue assignments:** last verified time is stored once per hour.
   If the source fails, last confirmed queues may be used for at most
   **24 hours**, while the run visibly reports an address verification error.
   Missing/expired verification prevents schedule alerts based on stale queue.
6. **Address event parser errors:** are registered as source failures,
   not quietly converted into green GitHub Actions runs.
7. **Published daily table corruption:** a present but unparseable current
   or next-day fact schedule yields an explicit source failure. A genuinely
   unpublished daily schedule remains normal, not a cancellation.
8. **GOП (capacity limitation):** recognized as capacity limits, **not**
   domestic power loss. Only a notice naming this exact house is eligible.
   Industrial/regional-only ГОП posts do not trigger household alerts.
   Reference: https://sies.gov.ua/zvernennya-gromadyan/najbilsh-zapituvana-informaciya/shcho-take-cherhy-vidkliuchen
9. **Real-source read-only checks:** an Actions `push` trigger on this
   feature branch runs the dry-run audit without Telegram credentials or
   GitHub write permissions. Production notification state is untouched.

## Release blockers / future tasks

**Do not merge this draft PR yet.**

- Independent area incidents sharing kind and territory still require stable
  per-incident identities and unambiguous closure matching. A coarse
  `official:status:{kind}:{level}` key is insufficient for multiple incidents.
- The GitHub repository and separate `bot-state` branch are public.
  The future checkpoint is now AES-256-GCM encrypted with a secret installation
  key. Historical public `main` commits remain exposed and are not erased.
- Exactly-once Telegram delivery is impossible with the current protocol:
  a successful send followed by checkpoint save failure may cause retry.
- Independent watchdog and failure notification are not deployed.
- Browser fallback session is cached **within one runner process only**.
- Verify actual provider correctness after changes. A green dry-run confirms
  source parsing, not electricity supply or that every bulletin is relevant.
- The PR is conflicting with `main` because active checks continuously
  commit checkpoint changes. Freeze `BOT_ENABLED`, migrate checkpoint, then
  resolve conflicts and deploy using the release checklist.
- An expired Cloudflare GH PAT will stop external workflow dispatches. Rotate
  before expiration and keep the native GitHub schedule as fallback.
- Remaining electricity providers need their own compatible, tested adapters.

The user must not post secret tokens, private address JSON or live state
contents in public GitHub issues or CI logs.

## Further audited work (22 November 2026, feature branch only)

- Independent official incidents with an explicitly dated start now use
  separate HMAC-scoped state keys. A close announcement that names the start
  closes only that incident. An undated close with multiple active candidates
  fails visibly; it never claims to restore the wrong event.
- The one-time migration preserves these per-incident status keys.
- Old closed incidents are pruned after 21 days. Unknown active incidents
  are not silently closed merely because time has passed.
- The public future `bot-state` checkpoint now uses AES-256-GCM with a
  random 96-bit nonce and authentication tag. The key is derived from private
  `POWER_CONFIG_JSON.state_key`; only an exactly empty bootstrap `{}`
  may be plaintext. Wrong keys or altered data fail closed.
- Migration reads old plaintext only from `main`, then stores encrypted
  pseudonymized data on `bot-state`. An automated test checks this path.
- A production-delivery branch gate rejects Telegram sends from feature refs.
- A read-only GitHub self-check workflow inspects successful production runs
  every 15 minutes and fails if no success occurred within 20 minutes. It is
  not independently hosted and no administrative Telegram alert is enabled.
- Latest observed tests: 252 passed in GitHub Actions.
  Repeat CI against the final head commit before cutover.

## Remaining hard blockers

- No truly independent notification channel alerts the administrator when
  GitHub itself is unavailable. A separate service and alert destination must
  be configured before claiming full outage detection.
- Exactly-once Telegram delivery remains impossible across a successful
  send followed by remote-state write failure.
- Events without explicit starts/IDs still cannot always be matched to
  independent concurrent incidents. Such ambiguous closures fail closed.
- A live read-only check is not a simulation of every official event or
  a guarantee that every real outage is detected.
- The PR remains a draft and conflicts with `main` until live checkpoint
  writes are frozen for a controlled migration. Do not merge prematurely.
