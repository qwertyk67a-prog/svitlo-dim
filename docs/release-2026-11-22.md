## Security and continued operation

- The plain `main/bot_state.json` no longer exists in the latest tree.
  Earlier Git commits remain public; encryption does not erase history.
- The `state_key` in private `POWER_CONFIG_JSON` must remain unchanged
  without an explicit re-encryption procedure.
- The Cloudflare worker remains configured with
  `ENABLED=true`, the five-minute Cron Trigger and
  `GH_WORKFLOW_TOKEN` as a Cloudflare Secret.
- `check.yml` still has its native GitHub five-minute cron as fallback.
  GitHub queues can delay jobs.
- The read-only GitHub health workflow checks for a recent successful
  production monitor every 15 minutes. This **is not an external watcher**,
  and it **does not notify a private Telegram administrator** yet.
- A successful Telegram send immediately before a remote checkpoint write
  failure can still cause a duplicate send after a retry. Exactly-once
  delivery is not guaranteed by Telegram sendMessage.
- Undated, ambiguous simultaneous official incidents are not represented
  as confirmed cancellations. Their ambiguity is explicitly reported.
- This verification establishes software operation, not the physical
  presence of electricity inside an apartment.

No passwords, tokens, raw address JSON or private identifiers were logged
or committed as part of this release report.
